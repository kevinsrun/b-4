# Scientific critic / safety agent

The reviewer of the autonomous discovery loop. It decides whether a claim is
carried by the evidence behind it, **before** the system writes it into the
research state or acts on it.

It reviews; it does not research. No experiments, no literature, no
hypotheses — it reads what the other agents produced, says what is wrong with
it, and names the agent that can fix it.

```python
from critic_agent import run_agent

envelope = run_agent({
    "claims": [{
        "claim_id": "claim-1",
        "statement": "Nisin reduces L. monocytogenes growth at 1 uM in BHI.",
        "result_ids": ["res-1", "res-2"],
    }],
    "previous_results": [result_one, result_two],
})

envelope.decision["status"]          # approve | approve_with_caveats
                                      # | reject | needs_more_evidence
envelope.recommended_next_action      # who should take it back, if anyone
```

## It does not approve by default

A critic that waves things through is worse than no critic: it launders
unexamined claims into the research state with a stamp on them. Approval is
what is left when no rule objects.

Three outcomes, and the third matters most:

| | meaning |
|---|---|
| `accepted_claims` | no rule objected |
| `rejected_claims` | an integrity failure; more data will not fix it |
| **neither** | **held** pending a followup |

A claim that is neither accepted nor rejected is *held*. Silence is not
permission. The orchestrator must not read "not rejected" as "accepted".

## What it checks

| check | issue type | routes to |
|---|---|---|
| conclusion follows from the result | `unsupported_conclusion` | analysis |
| provenance is classified | `unclassified_provenance` | evidence |
| simulated evidence not called validated | `misdescribed_provenance` | analysis |
| coverage / replication adequate | `insufficient_coverage` | planner |
| comparisons not confounded | `confounded_comparison` | planner |
| claims stay inside tested conditions | `unsupported_extrapolation` | planner |
| wording matches reported uncertainty | `overstated_certainty` | analysis |
| competing hypotheses distinguished | `hypotheses_not_distinguished` | planner |
| citations resolve | `missing_citation` | evidence |

**Integrity failures outrank gaps.** A claim that misdescribes its own
provenance is rejected, not deferred — running more experiments would not
make the wording true. The status logic encodes that ordering explicitly.

Each check is a standalone function in `rules.py`, pure and independently
testable, and each is written to stay quiet when it has nothing to say. A
critic that emits something for every claim trains the orchestrator to ignore
it.

## Routing

Work goes back to the real agent names used elsewhere in the system, so a
routing decision is directly actionable: `experiment_planner`,
`literature-evidence-agent`, `result_analysis_agent`. The critic recommends;
the orchestrator decides.

## A note on the dependency

This package depends on `bacteriocin-discovery` purely for the shared
contract (`contract.py`, `ids.py`). `experiment_planner_agent` sets the
opposite precedent — zero dependencies, contract shapes re-declared locally —
and that was deliberately **not** followed here: a critic whose copy of
`EvidenceType` can drift from everyone else's would validate against the
wrong vocabulary, which is the one failure mode this agent exists to prevent.

This makes the critic the second consumer of `contract.py` from outside its
home package, which strengthens the case for finally populating `shared/`.
Until that happens the dependency points at where the contract actually
lives.

One deliberate duplication remains: `claims_experimental_validation` is owned
here rather than imported from `result_analysis_agent`, because depending on
a sibling *agent's* internals would couple the reviewer to the thing it
reviews. A test asserts both implementations agree, so the copies cannot
drift silently.

## Tests

```bash
pytest packages/critic_agent/tests -q
```

Includes the three required cases — approval, rejection, and
needs-more-evidence routing — plus negative controls for every rule: a
disclaimer (`"not experimentally validated"`) must not trip the provenance
check, a hedged claim must not trip the certainty check, a single varying
condition must not count as confounded, and conditions inside the tested
range must not count as extrapolation. A rule that only ever fires is as
useless as one that never does.
